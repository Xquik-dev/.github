# Governance

This governance model covers every public Xquik-dev repository.

## Principles

- Discuss substantial changes in public issues or pull requests.
- Prefer evidence, user impact, security, and compatibility over preference.
- Record final decisions where contributors can find them.
- Protect confidential vulnerability reports until coordinated disclosure.

## Roles

### Project Lead

The project lead maintains the organization roadmap and governance model.

The lead appoints maintainers and resolves decisions without consensus.

Current project lead: [@kriptoburak](https://github.com/kriptoburak).

### Maintainers

Maintainers perform these duties:

- Triage issues and pull requests.
- Review code, documentation, dependencies, and releases.
- Protect public contracts and security requirements.
- Coordinate vulnerability response and disclosure.
- Publish releases through approved workflows.
- Enforce this governance model and the Code of Conduct.

Current maintainers: [@kriptoburak](https://github.com/kriptoburak).

### Reviewers

Reviewers provide consistent, technically sound pull request reviews.

Maintainers may recognize reviewers after several accepted contributions.

Reviewers cannot merge changes unless they also become maintainers.

### Contributors

Contributors report issues, propose changes, review work, or improve documentation.

All contributors must follow [CONTRIBUTING.md](CONTRIBUTING.md).

## Decisions

Use lazy consensus for routine, reversible decisions.

Leave proposals open for 5 business days when practical.

Any maintainer may approve routine changes after required review.

The project lead decides unresolved or urgent matters.

Document the decision and its rationale in the relevant public thread.

## Appointments

Maintainers evaluate candidates using these signals:

- Sustained, high-quality contributions.
- Sound security and compatibility judgment.
- Respectful reviews and community participation.
- Reliable completion of release or triage work.

Nominate candidates through a public governance issue.

Allow at least 7 days for community feedback.

The project lead records each appointment or removal publicly.

## Continuity

At least 2 maintainers should hold necessary administrative and release access.

The organization does not meet this continuity target yet.

Maintainer recruitment remains an active roadmap item.

## Conflicts

Disclose financial, employment, or personal conflicts before deciding related work.

Conflicted maintainers must avoid final approval when another maintainer is available.

Escalate unresolved conflicts to the project lead.

## Governance Changes

Propose governance changes through a pull request.

Explain the problem, expected impact, and migration steps.

Allow at least 14 days for public review.

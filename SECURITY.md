# Security Policy

## Reporting A Vulnerability

Report suspected vulnerabilities privately through the affected repository's GitHub private vulnerability reporting option when GitHub shows one.

Do not open public issues, pull requests, discussions, or support posts with exploit details, API keys, credentials, cookies, webhook signing values, account identifiers, screenshots with private data, or private routing details.

If private vulnerability reporting is not available, open a minimal public issue that only says a private security report is needed and names the affected public repository. Do not include technical details until a private channel is available.

## Scope

This policy covers public Xquik-dev repositories, SDKs, skills, docs, plugins, examples, and package metadata.

Public API, SDK, docs, package, or example issues that do not create a security risk can use normal GitHub issues.
